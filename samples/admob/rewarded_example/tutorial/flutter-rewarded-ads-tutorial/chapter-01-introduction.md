# 第 1 章：Rewarded Ads 简介

## 章节简介

在本章中，我们将介绍 Rewarded Ads（激励广告）的基本概念、使用场景和优势，帮助你理解为什么以及何时应该使用这种广告格式。我们还将概述奖励机制和实现流程，为后续章节的学习打下基础。

## 什么是 Rewarded Ads

Rewarded Ads（激励广告）是一种全屏广告格式，用户观看完整广告后可以获得应用内奖励。与传统的 Interstitial Ads 不同，Rewarded Ads 提供了明确的奖励机制，用户主动选择观看广告以获得奖励。

### 核心特征

Rewarded Ads 具有以下核心特征：

- **全屏展示**：占据整个屏幕，提供沉浸式体验
- **用户主动选择**：用户主动选择观看广告以获得奖励
- **奖励机制**：观看完整广告后获得应用内奖励
- **高参与度**：用户为了获得奖励而主动观看，参与度高
- **高收益潜力**：用户参与度高，带来更高的广告收益

## 使用场景和优势

### 典型使用场景

Rewarded Ads 最适合以下场景：

1. **游戏币奖励**：用户观看广告获得游戏币
2. **额外生命**：用户观看广告获得额外生命或继续游戏的机会
3. **解锁内容**：用户观看广告解锁特殊内容或功能
4. **跳过等待**：用户观看广告跳过等待时间
5. **获得道具**：用户观看广告获得特殊道具或装备

### 主要优势

使用 Rewarded Ads 可以带来以下优势：

- **提高用户参与度**：用户主动选择观看，参与度更高
- **提高广告收益**：用户完整观看广告，带来更高的收益
- **改善用户体验**：用户获得奖励，感觉有价值
- **增加用户留存**：奖励机制可以增加用户留存率
- **灵活集成**：可以在各种场景中灵活使用

## 与其他广告格式的区别

为了更好地理解 Rewarded Ads，让我们将其与其他常见的广告格式进行对比：

### Rewarded Ads vs Interstitial Ads

| 特性 | Rewarded Ads | Interstitial Ads |
|------|------------|-----------------|
| 用户选择 | 用户主动选择观看 | 在过渡点自动显示 |
| 奖励机制 | 有明确的奖励 | 无奖励 |
| 用户动机 | 为了获得奖励 | 被动观看 |
| 参与度 | 高 | 中等 |
| 收入潜力 | 高 | 高 |

### Rewarded Ads vs Banner Ads

| 特性 | Rewarded Ads | Banner Ads |
|------|------------|-----------|
| 显示方式 | 全屏显示 | 部分屏幕显示 |
| 用户交互 | 必须观看完整广告 | 可以忽略 |
| 奖励机制 | 有奖励 | 无奖励 |
| 视觉冲击 | 高 | 中等 |
| 收入潜力 | 高 | 中等 |

## 奖励机制概述

### 奖励类型

Rewarded Ads 可以奖励用户各种类型的应用内物品：

- **虚拟货币**：游戏币、金币、钻石等
- **游戏道具**：生命、能量、装备等
- **内容解锁**：特殊关卡、角色、皮肤等
- **时间跳过**：跳过等待时间、冷却时间等
- **功能解锁**：特殊功能、高级特性等

### 奖励数量

奖励数量可以是：

- **固定数量**：每次观看广告获得固定数量的奖励
- **随机数量**：每次观看广告获得随机数量的奖励
- **递增数量**：连续观看广告获得递增数量的奖励

### 奖励发放时机

奖励在以下时机发放：

- **广告观看完成**：用户观看完整广告后立即发放
- **通过 `onUserEarnedReward` 回调**：SDK 通过回调通知应用发放奖励

## 实现流程概览

实现 Rewarded Ads 的完整流程包括以下主要步骤：

### 1. 项目配置

- 添加 `google_mobile_ads` 依赖
- 配置 Android 和 iOS 平台
- 获取广告单元 ID

### 2. 加载广告

- 使用 `RewardedAd.load()` 方法请求广告
- 实现 `RewardedAdLoadCallback` 处理加载结果
- 保存加载的广告对象

### 3. 设置事件回调

- 实现 `FullScreenContentCallback` 处理广告事件
- 处理广告展示、关闭、点击等事件

### 4. 显示广告和处理奖励

- 在合适的时机调用 `show()` 方法
- 实现 `onUserEarnedReward` 回调处理奖励
- 发放奖励给用户

### 5. 资源管理

- 在广告关闭后释放资源
- 在 Widget 销毁时清理资源

### 6. 集成同意管理

- 实现用户同意管理（UMP）
- 在获得同意后加载广告

## 核心概念

在深入学习实现细节之前，让我们先了解几个核心概念：

### 广告单元 ID（Ad Unit ID）

广告单元 ID 是 Google AdMob 为你的应用分配的唯一标识符，用于标识特定的广告位置。每个平台（Android 和 iOS）都有独立的广告单元 ID。

### 广告加载（Ad Loading）

广告加载是指从 Google 广告服务器请求广告内容的过程。Rewarded Ads 需要在显示之前完成加载，这通常需要几秒钟的时间。

### 广告显示（Ad Showing）

广告显示是指将已加载的广告呈现给用户的过程。只有在广告成功加载后，才能进行展示。

### 奖励处理（Reward Handling）

奖励处理是指当用户观看完整广告后，应用发放奖励给用户的过程。这通过 `onUserEarnedReward` 回调实现。

### RewardItem 对象

`RewardItem` 对象包含奖励信息：

- `type`：奖励类型（字符串）
- `amount`：奖励数量（数字）
